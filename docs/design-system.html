How to use this document

This is the single design reference for IYKA-ARAM. Shared foundations govern every product; semantic themes adapt them for the expressive wellness website and the information-dense clinical operations interface.

Source of truth

src/app/design-tokens.css is canonical and this guide imports it directly. globals.css maps those values into Tailwind and holds component styles.

Two themes, not two systems

The website uses botanical colour and expressive display type. MIS and /admin use neutral surfaces, blue actions and Inter. Both share spacing, radii, elevation, motion, accessibility and status meaning.

Foundations

One system, two semantic themes

The brand should feel related everywhere without making a patient table look like a campaign page.

Public website + store

Calm, human and restorative

Bricolage Grotesque creates warmth and distinction; DM Sans keeps longer reading effortless. Forest is the anchor and gold is controlled emphasis.

MIS + admin

Clear, compact and dependable

Inter supports scanning, neutral surfaces reduce noise, and clinical blue signals actions. Status colours carry meaning, never decoration.

1 · Primitives--iyka-forest-800
Raw brand, neutral and status values.
2 · Semantics--green or --ops-action
Stable roles that express each surface.
3 · Components.v2-btn or .mis-card
Reusable patterns consume roles only.

Rule: components never reach past semantics to a primitive colour. This makes a theme adjustable without hunting through JSX.

Contrast

Measured, not estimated. The rule worth memorising: colour follows a semantic role, not personal taste. Use --gold-deep and --clay for accent text on ivory, --gold-light on dark, and keep --sage decorative rather than using it for small copy.

Gold buttons use dark forest text, not white. On light surfaces, gold should appear as a border, icon, rule or large fill; small text always switches to --gold-deep. Focus indicators use --focus-ring with a light offset so controls remain visible on both ivory and gold.

Foundations

Typefaces

The system has three deliberate roles. Bricolage Grotesque and DM Sans shape the public brand; Inter is the compact UI face for MIS and admin. Do not mix display typography into clinical data screens.

Bricolage Grotesque

Headings only — weights 300 and 700.

Token --font-displayWeights 300, 400, 500, 700 Note ships no true italic — see below

DM Sans

Body copy, labels, buttons, UI. Has a real italic: like this.

Token --font-bodyWeights 300–600

Never italicise a heading

Bricolage has no italic, so the browser synthesises a slanted fake. globals.css already sets font-style:normal on h1/h2/h3 em. Carry emphasis in gold instead.

Emphasis pattern

Wrap the emphasised clause in <em>:

Real people. Real clinic.
Real healing.

Do — measure headings in ch

max-width: 18ch;   /* ~2 lines, any tier */

ch scales with font-size, so the line length holds when a heading moves tier or the viewport changes it. Aim for 18–22ch on display headings.

Don't — measure them in rem

max-width: 22rem;  /* blind to the type */

A rem measure cannot see the type it holds. .sv-title sat at 22rem; when it moved up to the feature tier (max 4rem) the same measure broke a six-word headline onto five lines with the band two-thirds empty.

Everything animated must survive prefers-reduced-motion: reduce; globals.css already disables the fade-up keyframes under it.

Do — one-shot entrances

<Reveal> and .v2-reveal play once and stop. Hover transforms are fine — the visitor asked for them.

Don't — add a looping animation

The homepage carried five at once: a 3.5s hero text rotation, a 28s marquee, a 60s quote marquee and two gallery rows at 55s/65s. A wellness site should read calm. Two loops remain by choice: the modality strip under the hero, and the 3s scroll cue.

A row of content that does not fit is a swipe rail, not a marquee.

Calls to action

One primary action, site-wide: “Book a consultation.” There were seven competing labels — Book Now, Book a Consultation, Book Visit, Book Online, Join Class, Book a Free Call and Book / Enquire — which made the site feel like it wanted several different things from the visitor.

Do & don't

Do — use a heading class

<h2 className="v2-section-title"
    style={{ color: "var(--cream)" }}>

Don't — inline a size

<h2 style={{ fontSize:
  "clamp(2rem, 4.5vw, 3.2rem)",
  fontWeight: 700 }}>

Do — use the label modifier

<p className="v2-section-label
             v2-section-label-light">

Don't — override the colour inline

<p className="v2-section-label"
   style={{ color: "var(--gold-light)" }}>

Do — use the container helper

<div className="v2-container">

Don't — re-derive its width

<div className=
  "w-[min(90rem,100%-3rem)] mx-auto">

Do — gold-deep on cream, gold-light on dark

color: var(--gold-deep)   /* on cream */
color: var(--gold-light)  /* on dark  */

Don't — use --gold for text on cream

color: var(--gold)  /* 2.38:1 — fails */

Do — add a tier if a real new job appears

Define it as a token in design-tokens.css, give it a class, and document it here.

Don't — nudge an existing one

A 3.6rem next to a 3.8rem is how this site ended up with nine heading scales.

Practice

Clinical credibility

A wellness site earns trust by claiming less than it could. Three rules, each from a real problem found in the audit.

Separate recognition from collaboration

Two labelled groups: Recognised by (AYUSH, Ministry of Education, Govt. of Meghalaya) and In collaboration with (Decathlon, HP Tourism).

Don't put a ministry beside a retailer

One combined “Recognised & Collaborated With” heading over all five logos invited the reader to credit the brand with an endorsement it does not have.

Measured positioning

“Pioneering drugless healthcare in the North East.” Describes the practice without an unverifiable primacy claim.

Don't claim to be first

“The first…” appeared in three mutually inconsistent forms — first wellness centre, first start-up, first functional medicine startup — which undermined all three.

Patient stories carry a note

.v2-testimonial-note states consent, that these are personal accounts rather than clinical results, and that nothing is a promise of outcome.

Don't quote a clinical outcome

“Completely reversed my pre-diabetes” asserts a medical result in a patient's voice. Personal, non-clinical wording instead.

Practice

Governance & website repair order

Use the system as a decision filter, not a gallery of options. Fix the highest-impact inconsistencies first and migrate without breaking existing routes.

PriorityWebsite passDefinition of done
P0Visibility, focus and navigation contrastContent remains readable before hydration; every interactive element has visible keyboard focus; header text passes on every hero state.
P1Replace one-off colours, type sizes and spacingNo new hex values or near-duplicate clamps in components; section hierarchy uses the documented roles.
P2Consolidate repeated patternsPage heroes, CTAs, cards, labels, form controls and rails have one implementation per job.
P3Responsive and reduced-motion QA320px to wide desktop has no clipping; touch rails are usable; motion is optional and content is never animation-dependent.

Change process

Start with a semantic role, update design-tokens.css, map it in globals.css, update the live specimen, then run production build and visual checks.

Exception process

Do not add a value because one screen feels “slightly off.” Document a genuinely new job, test it in both themes, and only then add a token.

Minimum review: contrast, keyboard focus, touch target, empty/error/loading state, 320px layout, desktop layout and reduced motion.
